# OneSignal External ID Sync - Setup & Troubleshooting Guide

## Overview

This guide explains how to properly set up and troubleshoot OneSignal push notifications with External ID linking in your React app.

---

## 🎯 Key Concepts

### **Player ID vs External ID**

- **Player ID (OneSignal ID)**: Automatically generated by OneSignal for each device/browser. Format: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`
- **Subscription ID**: Specific to push subscription (may differ from Player ID)
- **External ID**: YOUR user identifier (`displayId` in your case, e.g., "LFB3Kf")

### **Why External ID?**

External IDs allow you to send notifications to users across multiple devices using YOUR identifier, not OneSignal's randomly generated Player ID.

## 📋 Initial Setup

### **Step 1: Get OneSignal Credentials**

1. Go to [OneSignal Dashboard](https://app.onesignal.com/)
2. Select your app (or create a new one)
3. Go to **Settings → Keys & IDs**
4. Copy:
   - **App ID** (e.g., `12345678-1234-1234-1234-123456789012`)
   - **REST API Key** (starts with `Basic `)

### **Step 2: Configure Environment Variables**

Create a `.env` file in your project root (copy from `.env.example`):

```bash
# Server-side (for REST API)
ONESIGNAL_APP_ID=your_app_id_here
ONESIGNAL_REST_API_KEY=your_rest_api_key_here

# Client-side (Vite requires VITE_ prefix)
VITE_ONESIGNAL_APP_ID=your_app_id_here
```

### **Step 3: Run Database Migration**

```bash
# Apply the OneSignal fields migration
psql $DATABASE_URL < migrations/0002_add_onesignal_fields.sql
```

This adds these fields to the `users` table:
- `onesignal_player_id`
- `onesignal_subscription_id`
- `onesignal_external_id_synced_at`
- `push_notifications_enabled`

### **Step 4: Configure OneSignal Web App Settings**

1. Go to **Settings → All Browsers**
2. Add your **Site URL** (e.g., `https://your-app.com`)
3. Enable **Auto Resubscribe**
4. Set **Permission Prompt** to "Custom Prompt" or "Slidedown"

### **Step 5: Test the Integration**

1. Login to your app
2. Open browser DevTools → Console
3. Look for OneSignal initialization logs:
   ```
   [OneSignal] Initializing...
   [OneSignal] Initialized successfully
   [OneSignal] Linking External ID: LFB3Kf
   [OneSignal] Player ID: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
   [OneSignal] External ID linked successfully
   ```

## 🧹 Cleanup: Remove "Ghost" Player IDs

If you're experiencing issues with old Player IDs persisting, run this cleanup:

### **Option 1: Browser Console (Recommended)**

```javascript
// Open browser DevTools → Console and run:
await window.clearOneSignalData();
// Then refresh the page
```

### **Option 2: Manual Cleanup**

1. **IndexedDB**: Chrome DevTools → Application → IndexedDB → Delete `OneSignalSDK`
2. **localStorage**: Application → Local Storage → Delete keys starting with `onesignal`
3. **Service Workers**: Application → Service Workers → Unregister OneSignal workers
4. **Clear Cache**: Application → Cache Storage → Delete OneSignal caches
5. **Refresh** the page

### **Option 3: Database Cleanup**

```sql
-- Clear all OneSignal data from database
UPDATE users 
SET 
  onesignal_player_id = NULL,
  onesignal_subscription_id = NULL,
  onesignal_external_id_synced_at = NULL,
  push_notifications_enabled = false;
```

## 🔍 Debugging External ID Issues

### **Check if External ID is Linked**

#### Method 1: OneSignal Dashboard
1. Go to **Audience → All Users**
2. Search for your user by Player ID or External ID
3. Check if **External User ID** field is populated with your `displayId`

#### Method 2: OneSignal REST API
```bash
curl -X GET \
  'https://onesignal.com/api/v1/players?app_id=YOUR_APP_ID&external_user_id=LFB3Kf' \
  -H 'Authorization: Basic YOUR_REST_API_KEY'
```

#### Method 3: Browser Console
```javascript
// Get current OneSignal state
const state = await window.getOneSignalStorageState();
console.log(state);
```

### **Common Issues**

#### 🚨 **Issue 1: Old Player ID Persists**
**Symptoms**: Same Player ID appears after logout/login/uninstall

**Root Cause**: OneSignal SDK caches Player ID in IndexedDB

**Fix**:
```javascript
await window.clearOneSignalData();
location.reload();
```

#### 🚨 **Issue 2: External ID Not Linking**
**Symptoms**: Player ID exists but External ID is empty in OneSignal dashboard

**Root Cause**: 
- User's `displayId` is `null` in database
- Login method not being called
- Race condition (SDK not initialized before login)

**Fix**:
1. Check if user has `displayId`:
   ```sql
   SELECT id, display_id FROM users WHERE id = 'USER_UUID';
   ```
2. Verify login is being called:
   ```javascript
   // Check console logs for:
   [OneSignal] Linking External ID: LFB3Kf
   ```
3. Check timing:
   ```javascript
   // In useOneSignal hook, ensure:
   // 1. state.initialized === true
   // 2. isAuthenticated === true
   // 3. loginAttempted.current === false
   ```

#### 🚨 **Issue 3: Notifications Not Delivered**
**Symptoms**: External ID linked but notifications don't arrive

**Root Cause**:
- Wrong External ID format
- User opted out of notifications
- Subscription expired

**Fix**:
1. Check subscription status:
   ```javascript
   const sub = await window.OneSignal.User.PushSubscription.getSubscription();
   console.log('Subscribed:', sub?.optedIn);
   ```
2. Verify External ID matches:
   ```javascript
   const user = await window.OneSignal.User.getUser();
   console.log('External ID:', user?.externalId);
   ```

#### 🚨 **Issue 4: Multiple Player IDs for Same User**
**Symptoms**: User has different Player IDs on different devices/browsers

**Root Cause**: This is EXPECTED behavior. One user can have multiple Player IDs.

**Solution**: Use External ID when sending notifications:
```javascript
await notificationService.sendNotification({
  externalIds: ['LFB3Kf'], // Use displayId, NOT Player ID
  headings: { en: 'Hello!' },
  contents: { en: 'You have a new message' },
});
```

## 📊 Architecture Overview

### **Client-Side Flow (useOneSignal Hook)**

```
User Login
   ↓
Auth Context Updates → isAuthenticated = true
   ↓
useOneSignal Hook Detects Auth
   ↓
Initialize OneSignal SDK
   ↓
Fetch User Profile (/api/user) → Get displayId
   ↓
Call window.OneSignal.login(displayId)
   ↓
Get Player ID & Subscription ID
   ↓
Save to Backend (/api/notification-preferences/player-id)
   ↓
External ID Linked! ✅
```

### **Backend Flow (API Routes)**

```
POST /api/notification-preferences/player-id
   ↓
Validate Request (onesignalPlayerId required)
   ↓
Update users table:
  - onesignal_player_id
  - onesignal_subscription_id
  - onesignal_external_id_synced_at = NOW()
  - push_notifications_enabled = true
   ↓
Return Success
```

### **Notification Sending Flow**

```
Backend Service
   ↓
Call notificationService.sendNotification({
  externalIds: ['LFB3Kf'],  // User's displayId
  headings: { en: 'Title' },
  contents: { en: 'Message' }
})
   ↓
OneSignal REST API
   ↓
POST https://onesignal.com/api/v1/notifications
   ↓
OneSignal matches External ID → Player IDs
   ↓
Push Notification Delivered to ALL user's devices
```

## 🛡️ Best Practices

### **1. Always Use External ID for Sending Notifications**

❌ **Bad**:
```typescript
// Don't send to Player IDs directly
await notificationService.sendNotification({
  playerIds: ['xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx'],
  ...
});
```

✅ **Good**:
```typescript
// Use External ID (displayId)
await notificationService.sendNotification({
  externalIds: ['LFB3Kf'],
  ...
});
```

### **2. Handle SDK Initialization Errors**

```typescript
const oneSignalState = useOneSignal({
  appId: process.env.VITE_ONESIGNAL_APP_ID,
  enabled: isAuthenticated,
});

if (oneSignalState.error) {
  console.error('OneSignal Error:', oneSignalState.error);
  // Show user-friendly message
}
```

### **3. Logout Properly**

When user logs out, clear their OneSignal session:

```typescript
// In your logout function
await window.OneSignal.logout();
```

The `useOneSignal` hook handles this automatically.

### **4. Test on Multiple Devices**

- **Desktop Browser** (Chrome, Firefox, Safari)
- **Mobile Browser** (iOS Safari, Android Chrome)
- **Native App** (if using BuildNatively)

Each device will have a different Player ID, but same External ID.

### **5. Monitor OneSignal Dashboard**

Regularly check:
- **Delivery → Reports**: Notification delivery rates
- **Audience → All Users**: User subscription status
- **Settings → API Keys**: Ensure keys are active

## 🚀 Production Deployment

### **Environment Variables**

Set these in your hosting provider (Vercel, Netlify, etc.):

```bash
ONESIGNAL_APP_ID=xxx
ONESIGNAL_REST_API_KEY=xxx
VITE_ONESIGNAL_APP_ID=xxx
```

### **Service Worker Setup**

OneSignal requires a service worker at your domain root:

1. Download from OneSignal dashboard: **Settings → All Browsers → Download Service Worker**
2. Place `OneSignalSDKWorker.js` in your `public/` folder
3. Ensure it's accessible at: `https://your-domain.com/OneSignalSDKWorker.js`

### **HTTPS Required**

Push notifications only work on HTTPS domains (or localhost).

### **Subdomain Setup (Optional)**

For better deliverability, use a subdomain like `push.your-domain.com`:

1. In OneSignal: **Settings → All Browsers → Setup**
2. Choose **My Own Site**
3. Follow subdomain setup instructions
