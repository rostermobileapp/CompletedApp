# Roster Tutorials — Screenshot Guide (Phase 1 draft)

This is an editorial capture checklist, **not application content**. No images have been captured and no demo accounts have been created. Use fictional fixtures only. Before capturing, verify labels on the device build and adjust this guide if a control has changed. Do not use production users, messages, payment details, or real contact information.

## Shared capture conventions

- **I** = iPhone 15, iOS, portrait, 393 × 852 CSS-pixel viewport (export at the device's native pixel dimensions). **A** = Pixel 8, Android, portrait, 412 × 915 CSS-pixel viewport. A row marked `I+A` means capture two separate images; add `-ios` or `-android` immediately before `.png` to the listed filename and track each capture separately. Unless marked otherwise, use I as the editorial master; the underlying app screens are shared across iOS and Android.
- Use **light mode**, text size 100%, portrait, no keyboard unless the step teaches input, and a clean status bar showing 9:41, full cellular/Wi‑Fi and battery. Hide system notifications, personal names, emails, phone numbers, payment tokens, QR codes linking to real accounts, and browser/dev chrome.
- Export **PNG (sRGB)** at native resolution. Prefer a lossless source; optimize to **under 350 KB per still** without obscuring text. Crop only blank device chrome or irrelevant lower-page content; keep the app header, the relevant control and enough context to identify the screen. Do not crop attribution, errors, paywall terms or essential accessibility labels.
- Use a **#3C82F4 blue 4 px circle/highlight** on the next tap target; use a blue numbered callout (1, 2) only when a shot explains multiple controls. Keep callouts away from text and faces; no fake controls or altered prices.
- The table's `Target / crop / annotation` names the required visible content before the slash, what to crop after `crop:`, and the control to highlight after `mark:`. Each row's alt text describes the actual UI and highlighted action without saying “image of.” `☐ Not captured` is the initial status; change to `☑ Captured` or `△ Needs retake` as you work. Numbered screenshots correspond to numbered tutorial steps; **every tutorial step has its own row**.
- **Locked tutorial preview** in the future UI is *not yet an app screen*: do not attempt to capture a fictional locked tutorials page. Capture the real current lock/paywall if it exists; the eventual tutorial placeholder should show the ID and description from this table.

1. Roster's captain is a team role, not a per-team paid subscription. Confirm precisely which captain operations work for a Free captain, because UI menus and server route checks can differ; the proposed paid captain captures deliberately use A3 until clarified.
2. The team-search screen finds a team by ID but has no visible join action on that screen. Do not annotate a nonexistent “Join” button. League search uses a **Request to Join** workflow rather than immediate entry.
