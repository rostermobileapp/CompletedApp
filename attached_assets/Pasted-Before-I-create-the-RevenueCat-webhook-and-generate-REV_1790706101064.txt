Before I create the RevenueCat webhook and generate REVENUECAT_WEBHOOK_SECRET, I need you to confirm exactly what your webhook-verification code expects. RevenueCat offers two different auth mechanisms and the secret's value differs depending on which one you implemented:

Static Authorization header — RevenueCat sends a fixed string I define as the Authorization header on every POST; your server checks it matches. In this case REVENUECAT_WEBHOOK_SECRET is just that string, and I set it when creating the webhook.
HMAC signature verification — RevenueCat sends an X-RevenueCat-Webhook-Signature header formatted t=<unix_timestamp>,v1=<hmac_sha256_hex>, and your server recomputes the HMAC-SHA256 to verify it. In this case REVENUECAT_WEBHOOK_SECRET is the signing secret RevenueCat generates when I enable HMAC signing (shown only once).
