GOAL
Restrict the "Subscribe via Roster" (Stripe checkout) button to DESKTOP BROWSER users only. Hide it everywhere else.

PLATFORM-SPECIFIC PAYWALL BEHAVIOR — final state

iOS (Natively WebView wrapper):
- Show: "Subscribe via App Store" only
- Hide: "Subscribe via Roster" button
- Hide: Any external payment links

Android (Natively WebView wrapper):
- Show: "Subscribe via Google Play" only
- Hide: "Subscribe via Roster" button
- Hide: Any external payment links

Mobile web browser (user opens roster website on phone Chrome/Safari, NOT in the wrapped app):
- Show: "Subscribe via Roster" button only
- This is desktop-class web checkout, just on a small screen — Stripe is allowed

Desktop browser (Chrome/Safari/Firefox on Mac/Windows/Linux):
- Show: "Subscribe via Roster" button only
- Existing behavior — no changes

WHY THIS MATTERS
- Apple App Store and Google Play both restrict external payment links inside their wrapped apps
- Showing "Subscribe via Roster" inside the iOS or Android app is a policy violation that risks app removal
- Web users (mobile or desktop) are not subject to App Store / Play Store rules — Stripe is fine there

DETECTION LOGIC
The existing useIosPlatform.ts hook detects isIos and isAndroid based on the Natively WebView wrapper. Use this hook as the source of truth.

Logic should be:
- If isIos === true → wrapped iOS app → hide Roster button
- If isAndroid === true → wrapped Android app → hide Roster button
- If neither → web browser (mobile or desktop) → show Roster button

Do NOT branch on screen size, viewport width, or user-agent mobile detection. The distinction is wrapped-app vs web-browser, not mobile vs desktop. A user on Chrome on their iPhone should see the Roster button. A user inside the iOS wrapped app should not.
